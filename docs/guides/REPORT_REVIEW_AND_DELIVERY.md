# 报告查验与有限交付

在 Analyst 输入框中，两个选项分别控制不同环节：

| 选项 | 用途 |
|---|---|
| **Jev source assistance** | 可选的公共检索片段判断与排序，不决定正式报告是否通过查验 |
| **Report review → Same model** | 默认由生成报告的业务模型，在独立上下文中检查来源支持 |
| **Report review → Jev** | 改由 Jev 检查报告与公开来源之间的支持关系；正文生成模型不变 |

两个选项可以分别开启。例如，可关闭 Jev 检索辅助而单独选择 Jev 报告查验。普通问答不因此变成 Jev 审批任务，市场 Refresh 也不能直接发布报告。选择会随报告任务保存，显式 Continue 沿用原任务选择；改变下拉框不会改写过去的报告审核记录。

报告查验组合程序检查和模型判断。来源身份、引用范围、数字与单位、计算回放等由程序核对；证据是否支持文字、是否混淆时间与执行状态等由选定审核器判断。Jev 的相关性和来源支持是不同任务，原生置信分数也不等于正确率。可选重排及单条语义判断不能证明报告完整或出版方说法真实。

查验失败会返回具体修改位置，让作者在保存草稿上修订。流程设有有限请求预算，包含实际审核请求和必要的格式修复。Same model 共用 4 次实际请求（含挑错、完整审核及格式修复），完整的双阶段查验通常最多两稿；Jev 按片段批处理，最多两稿、共用 16 次实际请求。两者均另预留一次最终稿查验，最多 2 次请求，不自动切换审核提供方。预算结束后，系统尝试保留已核验事实，删去未通过主张及依赖这些主张的结论；删减版本仍须通过最终检查。旧报告与存档仍保留当时的预算记录。

- **Sources checked**：保存的完整报告已完成必要来源查验。仍应阅读原文和限制。
- **Limited report**：仅保留最终查验通过的较小范围内容；原问题可能仍有无法回答的部分。
- **Evidence gap**：没有足够可交付的核验结论，保存固定的资料不足说明；它不表示市场事实已经通过来源审核。

报告详情和研究进度显示所用审核器。保存的来源查验、原文引用和计算输入可以继续打开核对；选择 Jev 不会关闭程序门禁，也不会把来源支持判定升级为事实真实性或投资表现保证。

Jev 使用完整任务、范围和绑定来源，分别判断四类支持状态和精确引文。没有统一 confidence≥0.8 门槛；正面批准要求支持概率超过其他状态之和，并有精确支持引文。这只是未校准的保守审批政策，不代表正确率，不用于检索排序。缺上下文、格式/网络失败和未评目标不能批准；私人持仓、预算和凭证不会为报告查验发给 Jev。

固定最小稿的过程说明，以及能从完整绑定来源的取得时钟逐项重建的自动时间声明，采用严格程序证明，避免让模型用新闻原文证明内部过程。任何非精确文案、遗漏/冲突时钟或新增外部事实仍须模型查验。旧 Jev v1 存档继续按原规则回放，新存档以 verified-process-v2 标记此分工。
