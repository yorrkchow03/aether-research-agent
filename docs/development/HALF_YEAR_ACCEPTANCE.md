## Memory and semantic components

- Evidence packs preserve exact passages, source hashes, version/update links,
  acquisition limits, conflicts and explicit budget gaps. Nonempty queries keep
  lexical relevance as default; semantic judgments start in shadow mode.
- Working memory stores goals, saved plans and full redacted tool artifacts.
  Native compaction retains original checkpoint/history, with summary calls
  counted separately. The default trigger is 48,000 tokens after real testing
  exposed repeated compression near the initial request size at 24,000.
- Correction experience requires existing evidence/review receipts and remains
  process guidance. A clean checkout does not inherit the owner's private
  corrections, data or investment context.
- Jev provides classification, relevance, relationships and public-claim support
  through one optional internal service. Scores/abstention are derived metadata,
  never original evidence. Missing permissions, timeout and repeated provider
  errors leave ordinary research available. Personal query text/context is
  excluded from optional public-source assessment.

The twelve-case matched Jev/Pro pilot preserves every original response,
format adaptation and failed/abstained result. Measured sequential provider time
was 22.35 seconds for Jev and 39.49 for Pro on these inputs. Pro token usage and
monetary cost were unavailable; semantic accuracy is unlabelled. The separate
24-document, nine-source integration batch returned **14 usable classifications,
9 abstentions and 1 invalid response**, without retries. It is not a whole-corpus
classification run or a representative accuracy estimate.

The final memory diagnostic replay includes 24 query/policy/time combinations.
On its three already inspected observed queries, relevance recalled all three
required passages; MMR recalled two and coverage one. These results do not
establish a general improvement. Human semantic labels and a larger untouched
study remain pending. See [Jev](JEV_PIPELINE_STATUS.md) and
[memory](MEMORY_QUALITY_STATUS.md) for protocols and limits.

the virtual environment and upstream checkouts. Data snapshots are separate
local artifacts. The source ZIP is prepared for review; nothing is pushed or
publicly published. No new automation, purchase or trade is created.
