# Conditional research acceptance

Date: 2026-10-30. This change adds optional explanatory chains, public historical
case navigation and paired condition diagnostics. Local Deep Agents/LangGraph,
Doubao Pro on the authorized Agent Plan endpoint, ordinary terminal analysis and
mandatory publication review remain the execution path.

## Implemented boundaries

- Old reports and short factual answers need no new fields. Explanations carry
  original source IDs, horizon, applicability, alternatives where supported,
  counterevidence, invalidation and uncertainty.
- Nested claims receive individual source-bound review targets. An overall
  explanation verdict cannot replace review of a foreign-source observation.
  Oversized review payloads fail before the provider request.
- Case memory retains reviewed-publication origins and original source hashes.
  Shared public cases reject private/context lineage, current library quarantine
  applies on recall, and dated origin-report feedback is shown as status pointers.
- Acquisition filtering precedes ranking and duplicate grouping. Repeated
  publications do not occupy all slots. Outcomes have independent clocks and
  never enter retrieval scores; future observations and outcomes remain excluded.
- Context budgets preserve whole cases. The SDK sends one representation;
  individual case reads paginate bounded outcome pages.

## Independent review

An independent Terra AI review identified source-binding, privacy, cutoff,
duplicate, budget, quarantine and diagnostic timestamp issues. These were fixed
with targeted regression cases. This review is an AI assessment, not human gold
or a guarantee of factual correctness.

## Synthetic Jev and Pro diagnostic

Sixteen synthetic inputs form eight condition-change pairs. Both providers use
identical eligible originals, claims, support criteria and a 0.8 acceptance
threshold, with one first attempt per case and a 30-second transport timeout.
This is a development diagnostic, not a held-out real-news benchmark.

The initial draft had observation/publication clock errors and two ambiguous
phrases. Its frozen inputs and first provider outputs remain unchanged. Version
1.1 was separately reviewed and run; initial outputs were not rescored. The
revised offline check passed all 16 fixture contracts and detected 47 deliberate
quote/condition/cutoff transport mutations. These are program checks, not model
accuracy results.

The empty eligible-source case makes no provider request and stays in both

Jev remains auxiliary. This diagnostic does not enable a new automatic final
condition checker or relax the mandatory Pro publication gate.

## Real harness acceptance

The first setup was rejected before model calls because the requested session
cutoff was a few seconds newer than its frozen data manifest. The verifier now
uses the manifest cutoff and preserves that zero-call failure.

The first actual product attempt published a 12-target source-reviewed report
and a fresh session genuinely queried its retained case through the terminal SDK
and reopened the originals. Its second task was not completed: mandatory review
rejected a process-history claim about the prior explanation that the cited
publisher pages did not establish, then the verifier's shared two-task HTTP
budget was exhausted. This failure is retained. An independent AI source check
also requested more precise wording about existing postponement client guidance
versus unknown guidance for a future replacement activation.

The verifier now allocates the declared HTTP bound separately to each task. A
new, explicitly revised acceptance attempt follows those source-review notes;
it is not substituted for the first attempt in any accuracy denominator.

The revised attempt completed both tasks. The report retained one reviewed
explanation, 16 source-bound review targets and a source-linked case. It took
216.23 seconds, eight author responses and two mandatory reviews (10 observed
Pro HTTP requests). The model autonomously corrected its first summary after
review feedback; this was not a first-draft approval.

A fresh session genuinely queried that case through the terminal SDK, matched
`event_status=delayed` and `network=Hoodi testnet`, reopened both originals and
submitted a source-reviewed answer. It took 123.64 seconds, 14 author responses
and one mandatory review (15 observed Pro HTTP requests). The source IDs, actual
case-recall event and separate task budgets are saved. No Jev sidecar was called
in these two product acceptance tasks. The standalone condition diagnostic is a
separate measurement and does not imply whole-product acceleration.

An independent Terra AI source review found the revised report's client-guidance
distinction and source scope adequate, with no remaining actionable issue in
that narrow assessment. This remains AI review of saved sources, not human truth
or a statistical quality claim.

## Delivery checks

The working-tree suite passed 860 tests, including legacy tool count and source
publication behavior. The running loopback service loads the new implementation
with the original Pro/Plan and shadow semantic configuration, preserves owner
state, and exposes the existing dashboard plus read-only case queries. The main
business tool count remains 12; per-indicator and per-condition tools were not
added. Historical reports without explanations remain unchanged; new reviewed
explanations start accumulating cases rather than fabricating historical output.

Final verification and source-export records are recorded with the delivery
checkpoint. Owner-local model receipts, source bytes and private state are
excluded from clean source exports.
