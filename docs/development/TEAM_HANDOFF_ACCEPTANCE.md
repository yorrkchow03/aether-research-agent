## 导出副本与交付凭据

交付的 `aether-source/` 为完整源码根目录，ZIP 内只有这一层根目录。`SOURCE_MANIFEST.json` 为源码与图的逐文件哈希；外层 `SHA256SUMS` 为 ZIP 的传输校验。

使用以下命令在导出目录而非作者工作区中验证应用导入、空状态和完整测试：

```bash
python scripts/dev/verify_clean_export.py --source dist/aether-source --output logs/team-clean-export.json
```

该命令从项目工作区运行；队友直接在解压出的源码中运行时，将 `--source` 改成 `.`。它检查源码 manifest，然后通过导出 `src/` 导入应用，复用当前已安装依赖，在临时空状态运行检查和离线测试。可选 `--wheel` 仍支持单独的 wheel 验收。本次不要求为共享源码另装打包工具。

干净副本的实际结果随源码附在 `HANDOFF_VERIFICATION.json`，交付目录外层同时保留一份。这是额外交付元信息，不属于 `SOURCE_MANIFEST.json` 的源码输入；其字节由 ZIP 传输校验覆盖。不把历史工作区的结果当作导出副本通过，也不把这项检查描述为重新安装所有依赖、真实联网或模型质量测试。

## 保留的边界

- 当前终端在本机执行，并通过 Unix socket 访问同一任务的数据服务；不是容器隔离或多用户服务。
- 四个内置 skills、模型可见工具、SDK、历史研究接口是不同层次；扩展前按 TEAM_HANDOFF 确认所改位置。
- 提示和方法可扩展，计划、来源、数值/时间和发布核验的契约需要保留与回归。
- 离线交接验收没有发起付费研究。随后单独授权的 Jev 接通测试输入 588 token、输出 63 token，事件状态合成样本符合预期，耗时约 1.223 秒；不是准确率评测。未发起新的豆包研究、交易、Git 初始化、远端推送或公开部署。Linux/Python 3.12/3.13 的 CI 配置不等于本机已运行过这些平台。
- 原有本机数据和旧交付包保留在本地；源码副本不含凭证、个人记录或课程成员资料。
